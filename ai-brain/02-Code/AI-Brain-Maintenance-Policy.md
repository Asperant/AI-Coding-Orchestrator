# AI-Brain Maintenance Policy

Purpose: prevent the AI-Brain from becoming too large or redundant.

## When to create a new file

- When the concept is reusable and distinct
- When an existing file would become overloaded by adding it
- When the new file adds a clear operational purpose

## When to update an existing file

- When the new information extends an existing rule, checklist, or map
- When the topic already has a clear owner file
- When a small targeted addition preserves structure better than a new file

## When to create an example

- When a template exists but output quality still needs calibration
- When a real decision, bug fix, or review can teach better than abstract rules

## When to recommend archive/merge

- When two files overlap heavily
- When a file is no longer part of active onboarding or execution
- When navigation surfaces grow noisier than the value they add

Use recommendations only unless explicit approval is given.

## Monthly maintenance checklist

- Review onboarding surfaces for clutter
- Review overlapping files
- Check whether examples still match current standards
- Check whether decisions and lessons are being saved to the right place
- Review whether new files actually changed real usage

## Link audit recommendation

Run a periodic wiki-link audit, especially after adding navigation or classification notes.

## Approval rule

No deletion should happen without explicit user approval.
